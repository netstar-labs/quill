# Decisions

Choices made where the design left room. Newest last. **Every row was accepted by the owner on 2026-10-28**; a row that carries its own date records a specific answer or
request given that day, and a rejected row would be
struck through and kept. "The reference" is the existing implementation reviewed in [review.md](review.md).

| # | Decision | Why |
|---|---|---|
| 1 | The project is **quill**: package `quill`, module `github.com/netstar-labs/quill`, CLI `quill`. The library is the root package, with `cmd/`, `internal/`, `examples/` and `docs/` beside it. **Accepted 2026-10-28.** | A short name that is easy to type. |
| 2 | **Build fresh** from this design, porting the reference's behavioural tests that still apply, instead of deleting code from the reference. | The sharding, frontier and read-only logic is woven through the reference's single large core file; deleting it in place risks leaving half of it behind. Tests carry its hard-won recovery behaviour, so they travel; the code is rewritten smaller. |
| 3 | **The frame bytes are the reference's, unchanged**; file names, state files and layout are free to change. **Accepted 2026-10-28**, "unless there is a performance advantage to altering it". | None found: the reference's own profiles (**reported**) show appends bound by memory copying and allocation and reads by syscalls, not by decoding, so the frame is not the bottleneck. The golden tests that pin the frame stay valid. *Stage 2 audit, owner-approved 2026-11-03, A7-15: the reference's share of read CPU spent in syscalls was removed; the conclusion does not rest on it.* |
| 4 | **A log is a directory.** `Open(dir)` returns a `Log` for one topic and takes that directory's lock. Multiple topics are multiple logs, in one process or several. **Accepted 2026-10-28.** | A directory is the unit of ownership, state, retention, backup and deletion. It removes the topic registry, the case-collision check, the 230-byte topic limit, per-topic maps in every state file and the global byte cap, and lets different processes own different topics. Cost: many topics mean many directories, locks and descriptors. |
| 5 | **One lane per log.** Sequence numbers are assigned under the log's mutex; there is no router and no CAS counter. | At one lane file order is sequence order: no merge, no cross-shard frontier, `ScanAll` ordered. Measured on the reference: reads were faster from the start of a log at one shard than at four ([review.md](review.md), finding 1). *Stage 2 audit, owner-approved 2026-11-03, A7-15: the ratio was removed; quill's own measurements are in [benchmark-baselines.md](../audits/benchmark-baselines.md).* |
| 6 | **A per-log format marker file, `quill.format`**, holds `quill/1` and a random 128-bit **log ID** in hex (`quill/1 3f9a…`); written when a log is created, required on open. A marker newer than quill knows is refused with `ErrFutureVersion`. **Accepted 2026-10-28.** | The reference's frame has no version (a documented limitation), so a format change cannot announce itself. A marker file fixes that without changing the frame; a header in each segment would change the bytes. The log ID ties a consumer's offset file to the log it belongs to, so a log that is recreated or replaced does not silently inherit offsets (decision 36). *Stage 2 audit, owner-approved 2026-10-30, A1-13: every path that reads a log's marker gives `ErrFutureVersion` for a newer one, `Archive` on its destination included; it returned `ErrCorrupt`. The three loads of `quill.format` (`Open`, `OpenReader`, `Archive`) are now one function.* |
| 7 | **Variable-length frames only.** The fixed-width format and its configuration are cut. | A second recovery path and several of the reference's documented limitations, for an O(1) cold start that `.idx` sidecars can provide later. *Stage 2 audit, owner-approved 2026-11-03, A7-15: the counts of limitations (three of thirteen) were removed.* |
| 8 | **`quill.tail` is the single durable marker.** One small strict-JSON file `{seq, seg, off, maxseg}`: the last durable sequence, the active segment id and byte offset that are durable, and the highest segment id ever used. The writer rewrites it (temp file, fsync, rename, no directory fsync) after each flush that changed it, and before any segment is deleted. A `Reader` reads up to it and no further, and does **not** probe whether a writer is live. **No feed for a shipper. Accepted 2026-10-28** (a marker for external readers; nothing for a shipper); the choice to trust the marker alone, with no liveness probe, **confirmed 2026-10-28**. | The marker closes the hazard that a reader sees bytes still in the page cache which an OS crash would drop and the writer would later reuse. It also replaces separate head, segment-id and frontier files: the head survives expiry of every segment because the marker keeps `seq`, and a deleted id is never reused because it keeps `maxseg`. After a process crash the marker can be one flush behind the disk; after an OS crash, because the rename is not directory-synced, it can be older by the flushes since the last directory fsync, which happens at rotation, at `Close` and before any deletion (decisions 39, 40, 65). Either way a stale marker hides records and never exposes them, and `quill recover` or the writer's next open republishes it. |
| 9 | **One offset file per consumer**, `consumers/{name}`, written (temp, fsync, rename) only by the process holding that consumer's lock (`consumers/{name}.lock`, `flock`); used by in-process and external consumers alike. The file holds `<log id> <next> <protect>`, where `protect` is `0` or `1` (decision 57). Opening a handle or `register` creates it if absent, at the first retained sequence (at sequence 1 when a damaged oldest segment left a hole below it, decision 38; decision 41). `Commit(next)` accepts any value from the first retained sequence to `Head + 1`, including a rewind (decision 36). **Accepted 2026-10-28.** | An external consumer cannot write a file the log's writer owns, and the writer's retention needs to see every consumer. One mechanism for both removes a code path. Each file has exactly one writer, so no cross-process merge is needed. Cost: each `Commit` is a file write and fsync, so a consumer commits once per batch, not per record (confirmed 2026-10-28). |
| 10 | **Sequences are contiguous.** The next sequence after open is the last valid frame's sequence plus one; if `quill.tail.seq` is greater than that, acknowledged data is missing and `Open` fails with `ErrCorrupt` (decision 39). `Head()` is the last *flushed* sequence. The numbers of a crashed unflushed suffix are reassigned. There is no separate durable-sequence call. | Readers and consumers see only durable records, so nobody can hold an unflushed number; the reference's gaps existed because several shards flushed independently. Callers must `Flush` before acknowledging a sequence upstream, which the reference's docs already require. A deviation from the reference. **Accepted 2026-10-28.** |
| 11 | **`OpenReader(dir)` is lock-free** and returns a `*Reader` with `Read`, `ReadWait`, `Scan`, `ScanAll`, `Records`, `Follow`, `OffsetForTime`, `Head`, `Stat`, `Check`, `Consumer` and `Close`. It re-reads `quill.tail` and re-lists segments on each call, so there is no `Refresh`. `ReadWait` polls. A reader holds segment descriptors, so retention deleting a segment cannot break a read in progress. | The stated need: another process consumes lazily. A damaged or missing segment is a hole: reads stop before it with a `GapError` (decision 38), and there is no option to skip one silently. |
| 12 | **Nothing holds back retention by default.** No consumer is protected unless it asks (decision 57). The in-memory `Dropped` counter counts segments deleted while some consumer had not read past them, per log, and resets on restart. **Accepted 2026-10-28.** Verified on the reference: its log-wide switch is a plain `bool` (off) and its server never sets it. | Consequence for a lazy consumer: unless it is protected it finds nothing if it starts after `Retention`, so `Retention` must exceed the worst delay of an unprotected consumer, be negative, or the consumer must be protected. A persisted counter is not built. *Stage 2 audit, 2026-10-31, A3-27: at a seal the caps judge "some consumer had not read past" by the offsets the last prune pass read (or `Open` read, before the first pass), not by a fresh listing: listing `consumers/` under the log's lock made every `Append`, `Flush` and `Read` wait for as many file reads as the directory has entries, and another process can add entries. So `Dropped` can lag a consumer that moved, or was created, since that pass by up to `PruneInterval`; `Prune` refreshes it at once.* *Stage 2 audit, owner-approved 2026-10-31, A5-18: a deletion that passes a consumer's offset is logged at `Warn` with the consumer's name, its offset and the segment's last sequence (the segment's `Info` line names nobody), whether the consumer is protected and overridden by a cap or not protected at all, and `quill prune` prints `dropped N`, the count for that pass. Nothing is persisted: the counter still resets on restart, and a consumer that fell out of retention is shown by deriving it from the files (decisions 36 and 66).* |
| 13 | **Each log has its own flush goroutine.** Within a log, a flush holds the log's lock through write and fsync, as the reference does. Moving the fsync outside the lock is a measured follow-up. | Logs then flush in parallel by construction. The reference flushes its topics serially, so T dirty topics cost T fsyncs back to back (**verified** in its source; the cost is not measured). |
| 14 | **No dependencies.** `go.mod` has no `require` line. | Smallest possible audit and build surface. A check that needs a dependency is copied with the reason written in the file. |
| 15 | **Segments are read with `pread`: no mmap, no segment cache, no vendored code.** The log keeps the active segment's descriptor open and a read is one `ReadAt` into a pooled buffer, bounded by the durable position and decoded in place (`Scan` payloads alias the buffer and are valid only during the callback). Every other read opens the segment, reads and closes it. A small descriptor cache, or a mapped read path for sealed segments, is a measured follow-up (roadmap). | **Measured** on the reference's access pattern (one segment, small frames, CRC checked, 100 records per read, warm cache, single thread; macOS host and Linux container): a cached mapping was the fastest per read, a held-open `pread` was somewhat slower, open-per-call slower again, and a map-and-unmap per call the slowest. Draining a large backlog, the mapped path decoded faster than `pread` on both. Both are far above any durable write rate, so the extra per-read cost of `pread` does not matter where a consumer's work is real. What `pread` removes: the cache and its reference counting, the vendored code and its third-party notice, the remapping needed to see appended bytes (the reference maps the active segment afresh on every read for that reason, **reported**), and the class of crash where a truncated mapped file faults a reader (**reported**: the reference fixed one such crash and lists the rest as a limitation). With cross-process readers (decision 11) and a writer that truncates a torn tail on recovery, that class matters here. Not measured: a backlog larger than memory read from a real disk, where sequential `pread` with large chunks should be limited by the disk either way (**inferred**); phase 4 measures it. Supersedes the earlier plan to wrap `syscall.Mmap`. **Accepted 2026-10-28**, with the real-disk backlog measurement as a phase-4 check. *Stage 2 audit, owner-approved 2026-11-03, A7-15: the reference's per-read timings and drain rates were removed and the design conclusion kept (`pread` is slower than a cached mapping by an amount that does not matter at any durable write rate); quill's own read and drain measurements are in [benchmark-baselines.md](../audits/benchmark-baselines.md).* |
| 16 | **Limits are the reference's where they still apply:** payload at most 64 MiB − 32 bytes (so the frame body stays within the limit recovery enforces, decision 69), a declared frame over 64 MiB is corruption, segment file at most 1.5 GiB, `SegmentBytes` at most 1 GiB (*amended, Stage 2 audit, owner-approved 2026-10-30, A1-25: and `SegmentBytes` plus one flush's overshoot under the file limit, decision 60 d*). Consumer names `[a-z0-9_-]`, 1–200 characters, a leading underscore reserved, except the archiver's own `_archive` (decision 41; *amended, Stage 2 audit, owner-approved 2026-10-30, A1-32*). A log's name is its directory's name and quill imposes no limit on it. | They protect the file system and bound allocation. The reference's topic-name length limit existed because a topic became part of a segment file name; it goes with decision 4. *Stage 2 audit, owner-approved 2026-11-03, A7-15: its number was removed.* |
| 17 | **`quill.lock` lives inside the log directory** and the writer's `flock` is taken on it. There is no call that removes a directory under the lock. | The reference kept the lock beside the directory so a truncate-the-directory option could delete it while holding the lock. Without that option the directory is self-contained. A caller who wants an empty log removes the directory first. |
| 18 | **`At` is whole Unix seconds**, so retention is meaningful at second granularity only. | It is part of the frame. |
| 19 | **Linux and darwin only.** Other platforms do not build. | The directory lock is a unix `flock`. |
| 20 | **The source is split by responsibility**, none over about 600 lines. | The reference's core is one file of thousands of lines, which cannot be audited in one sitting. *Stage 2 audit, owner-approved 2026-11-03, A7-15: its line count was removed.* |
| 21 | **The performance gate is a recorded baseline** for each benchmark in phase 4 (six runs, one machine), with no later regression beyond run-to-run noise. | Quill changes shape, not speed, and a number invented in advance would be arbitrary. The orientation figures in [scope.md](scope.md) are quill's own recorded baselines (*amended, Stage 2 audit, owner-approved 2026-11-03, A7-15: they were once the reference's at one lane; none of the reference's remains*). Quill's flush adds a marker write and fsync to the data fsync (decision 8), so durable-write throughput is expected to be lower; the baselines state that cost and do not hide it. |
| 22 | **No `LICENSE` while the repository is private**; no third-party code ships (decision 15), so no `THIRD-PARTY-NOTICES`. | Unlicensed means all rights reserved until release; the owner decides when a licence lands. **Confirmed 2026-10-28.** |
| 23 | **v0-forever versioning**, with the format marker versioned independently of the module. | Tags `v0.y.z`, never `v1`; a stable format is expressed as a frozen marker, not a major version. |
| 24 | **`MaxBytes` is per log and is checked at every segment seal as well as every prune pass.** The active segment is never deleted. It overrides consumer protection (decision 57). Default off, **accepted 2026-10-28**. | A time window alone does not bound size. Checking at the seal bounds the overshoot to one segment and one batch (decision 46); the reference checks only on a timer, so a burst can overshoot by a whole interval (**reported**). The default stays off so data is not deleted by a number the owner never chose; `check` warns on an unbounded log. |
| 25 | **`MinFreeBytes`** (default off): measured with `syscall.Statfs` on the log's directory, checked at each seal and prune pass. Below the floor the log deletes its own oldest sealed segments; with none left to delete, appends fail with an error wrapping `ENOSPC`. Like `MaxBytes` it overrides consumer protection (decision 57). | The backstop when several logs or other programs share a disk and no global budget exists. The reference lists it as not planned (**reported**); with one log per directory it is the only way to react to the disk's actual state. `Statfs` is standard library on both platforms (**verified** on macOS, compiled for Linux). It cannot free another process's bytes and `Bavail` excludes reserved blocks. *Stage 2 audit, owner-approved 2026-10-31, A5-22: a free-space floor that cannot be met or checked is reported. `Err()` returns an error wrapping `ENOSPC` while `diskFull` is set and an error wrapping the `statfs` failure when a pass cannot read the free space (one failure is the trigger; there is no count of consecutive failures), and both clear at the first pass that reads room. `Stat()` gains `DiskFull` and `FreeBytesAtLastPass`, and the clearing of `diskFull` is logged at `Info`. A `diskFull` already set is kept while `statfs` fails: the floor is unknown, so the last state stands and `Err()` reports both.* *Stage 2 audit, owner-approved 2026-11-03, L1-10: the log records are not all one per transition. The `Warn` for a floor that cannot be met ("free space below MinFreeBytes with nothing left to delete; appends will fail") and the `Info` for its clearing are written once per transition. The `Warn` "cannot read free space" is written by every pass whose `statfs` fails and by every seal whose `statfs` fails (the caps run at each seal, as the decision says, so a `Roll`, or any flush that rotates (an `Append`'s inline flush, `Flush`, `Sync`, `Close` or the flusher's), reads the free space too, and a `Prune` whose age rotation seals reads it at the seal and again in the pass), so six failing passes or seals write six, and no transition guard is added: a failing `statfs` is an alertable condition and the repeat says it is still failing. Tests pin both, the seal path and the pass path. Documentation only; behaviour is unchanged.* *Stage 2 audit, owner-approved 2026-11-03, A3-32: the floor overrides protection, and this is documented, not changed. When the filesystem is below the floor the writer deletes the oldest sealed segments even if a protected consumer has not read them. It reads the free space once with `statfs`, then counts each segment as freeing its size (it does not read again after each unlink) until the estimate reaches the floor or no sealed segment is left; the clock guard does not apply, because it limits the age sweep only; the active segment is never deleted. Another process's disk use on the same filesystem can therefore cost this log its history, protected consumers' unread segments included, which is the intended use of the floor on a shared disk ("another application or log can use the room first"). The consumer loses records, and the `Warn` "deleted segment past a consumer's offset; it has lost records" (decision 12) and `Stat().Dropped` are how that is seen. A test pins it (a protected consumer at 1, a `statfs` seam below the floor, a prune pass). Documentation only; behaviour is unchanged.* *Stage 2 audit, 2026-11-03, A7-1: the estimate counts every segment the pass deletes, not only those the floor adds. The segments the age sweep and the `MaxBytes` cap already chose in the same pass are credited with their size before the floor is compared, so a reading just below the floor that they make up for deletes nothing more, and a larger shortfall deletes only the further segments it still needs. Before, those segments were not credited and a pass slightly below the floor could delete every sealed segment, protected or not. `Stat().FreeBytesAtLastPass` stays the raw `statfs` reading.* |
| 26 | **`MaxPayloadBytes`**, default and ceiling 64 MiB. A record-count cap is separate (decision 33). | Cheap and lets a log refuse a runaway record at the door. |
| 27 | **`Roll()`** seals the active segment on demand; the `roll` CLI verb works offline only, because it needs the writer's lock. | A segment must be sealed before it can be archived or reached by retention. A live writer calls it in-process. There is no control socket to reach a running writer from the CLI. |
| 28 | **Archiving is a consumer.** `quill archive` is a **protected** consumer named `_archive` that copies sealed segments to a destination directory with CRC verification and writes the destination's `quill.tail` and `quill.format`, so an archive is itself a log that `OpenReader` can open. It runs beside a live writer (it reads only immutable sealed segments). | Reuses decision 9's machinery instead of adding a hook. Disk caps still win, so archiving can fall behind under pressure; that is the right priority for a rolling log. Shipping archives elsewhere is the operator's `rsync`. |
| 29 | **`quill.policy`** (strict JSON): the `Config` the writer last opened with — every retention and cap setting, `ConsumerTTL`, segment size and payload limit. Informational: `Config` at open is authoritative and rewrites the file. Offline tools read it. It is parsed tolerantly (unknown fields ignored) and a parse failure never blocks `Open`; an offline tool that cannot parse it refuses to act on it (decision 48). *Stage 2 audit, owner-approved 2026-10-30, A1-91: a `quill.policy` with no `retention` (`{}`, `null`, only unknown fields) cannot be parsed: every writer writes `retention`, an off one as `-1ns`, and a missing one would be acted on as 0, the 24 h default.* *Stage 2 audit, 2026-10-31, A5-39: a failed write of `quill.policy` still never fails `Open`, but it no longer leaves the previous writer's file in place for `check`, `ls` and an offline `prune` to read as this writer's settings. The writer removes the file (best effort), keeps the error in `Err()`, logs a `Warn`, and writes again at each flush, each prune pass and at `Close`, until a write succeeds. Until then offline tools see no policy: `prune` refuses without flags, `check` warns and reports the log unbounded. If the removal fails too, the old file stays until a retry succeeds. No flag or field is added.* | A log is managed as a directory, and a tool looking at one directory cannot know its limits otherwise. **Accepted 2026-10-28.** |
| 30 | **Disk-full and write-failure behaviour** (decision 37): a flush writes at the durable offset and, on any write error, truncates back to it and keeps the records buffered (up to `MaxBufferBytes`, then appends fail fast with an error wrapping the cause); an **fsync** error is fatal and sticky. Quill adds tests that run both for real. | The reference derived its disk-full behaviour from its code but never ran it on a real full disk (**reported**). A container with a small `tmpfs` covers space exhaustion; short writes and fsync failure need the fault-injecting file-system seam (decision 52). |
| 31 | **`ConsumerTTL`** (default off). A protected consumer is **stale** as defined in decision 45; it then stops protecting segments (the TTL applies to protected consumers only). Its file is never deleted automatically; `Stat().StaleConsumers` reports it. A caught-up consumer is never stale. | The reference has no expiry (**reported**; its guide says a registered consumer that never commits pins segments forever), so one dead consumer can hold the disk until a cap fires. The mtime is free: every `Commit` and `register` writes a new file (inferred; tested). Keeping the file means a returning consumer resumes instead of restarting at 0 and reprocessing everything; deleting is an explicit `DeleteConsumer`. The default stays off because silent expiry changes who keeps their data. **Accepted 2026-10-28** (default off). |
| 32 | **Disk use is measured, not estimated.** `Stat().Bytes` is the sum of segment sizes; `Stat().Records` is `Head − first retained + 1` minus the records inside holes (hole sizes follow from contiguity). The size estimate `records × (average payload + ~16)` is for planning only. | **Verified** on the reference at one lane: its byte count equalled the bytes of the segment files at several payload sizes. Quill's own framing cost, and the test that its byte count equals the bytes on disk (T17), are in [scope.md](scope.md) ("Knowing the size"). Contiguous sequences (decision 10) make the count exact where the reference's would not be. *Stage 2 audit, owner-approved 2026-11-03, A7-15: the reference's framing sizes (a range of bytes per record) were removed; the `~16` planning estimate stands on quill's own figure (12 to 18 bytes per record across payloads of 0 to 16 KiB and sequences up to about two million, computed 2026-11-03 from quill's own `frameLen` over that grid; 12 at the small end, one more byte per extra varint byte as sequences grow).* |
| 33 | **`MaxRecords`** (default off): keep roughly the newest N records, evaluated in the same pass and at the same seals as `MaxBytes`, segment-granular, never deleting the active segment. It does not replace `MaxBytes`. | Requested by the owner and **accepted 2026-10-28**: with the count and the record size known, a count is a natural way to say how much to keep. A count bounds disk only if record size is bounded, so the worst case is `MaxRecords × (MaxPayloadBytes + 32)`; `MaxBytes` remains the hard guarantee. Cheap: per-segment counts come from the first and last sequence. |
| 34 | **Write durability is a setting over one mechanism.** `Flush` makes records durable; `Sync(ctx, seq)` waits for a sequence to be durable, as group commit (producers append under the lock, release it, and wait for the next flush covering their sequence); `Config.SyncAppends` makes every append do that. The default is buffered. Consumer protection is documented as a retention setting only. | The format and the guarantees do not depend on the mode, so this is a policy, not a design commitment. The wait reuses the flush broadcast that `ReadWait` already needs. A flush holds the log's lock through its write and fsync (decision 13), so appenders queue behind it; waiters hold no lock, and the next flush covers everything appended meanwhile, so concurrent producers still share one fsync. `Sync` signals the flusher at once, so a lone producer does not wait for `FlushInterval` (decision 42). A failed flush returns the error to the caller, but the records stay buffered and may still become durable, so an error from `Sync` means *unknown*, not *lost*, and a producer that retries must tolerate duplicates (decision 37). A four-producer measurement on one log scaled about 3.5× over one in a container (**measured**, noisy; not measured on the host), which suggests flushes already overlap at the filesystem, so the gain over a plain `Flush` loop is unproven. **Accepted 2026-10-28.** |
| 35 | **Readable output: `-json` on `quill cat`, `read` and `tail`.** Newline-delimited JSON, one object per record: `seq`, `at`, `time` (RFC 3339 UTC), `len`, and exactly one of `payload` (a JSON string, only when the bytes are valid UTF-8) or `payload_b64`; `-b64` forces base64. The verbs read through `OpenReader`. **Requested by the owner 2026-10-28; the field layout accepted with the rest of this log.** | The segment files are binary (see scope.md), so a human or a script needs a way to see records. A lossless encoding matters more than a pretty one: Go's JSON encoder silently replaces invalid UTF-8, so a payload that is not valid UTF-8 must take the base64 path, and a test pins it. Newline-delimited objects stream, pipe into `jq`, and cannot be corrupted by a payload that contains a newline because JSON escapes it. *Stage 2 audit, owner-approved 2026-10-30, A1-50: the `payload` string also escapes DEL (U+007F) and the C1 controls U+0080 to U+009F as `\u00XX`, which `encoding/json` passes raw and a terminal may act on (U+009B is the CSI introducer); the text form already escaped them. The JSON stays valid and lossless; for those characters the bytes are no longer what `encoding/json` would produce, and the differential test says so.* *Stage 2 audit, owner-approved 2026-11-03, A3-3: the text output applies the same escaping to every string that comes from the disk, a log name in `ls`, a consumer name in `consumers`, a path in a `check` problem or an error message (the whole string is quoted when any character is not printable; a plain name is printed unchanged and the `-json` shape is unchanged), so a file name cannot inject a line or a terminal sequence. The one escaper (`appendQuoted`) now also writes a byte that is not valid UTF-8 as `\xNN`.* *Stage 2 audit, owner-approved 2026-10-30, A1-57: `stat`, `check` and `consumers` also take `-json`, and their shape is now fixed in scope.md. Every key is lowercase; `stat` writes each hole as `{"from":N,"to":N}` and an empty `holes` as `[]`, where it used to write `{"From":N,"To":N}` and `null`.* *Stage 2 audit, owner-approved 2026-11-03, A3-24: the `payload` string also escapes the Unicode format characters (category Cf), which `encoding/json` passes raw and which the text form already escapes because `strconv.IsPrint` rejects them: the bidi controls (U+202A to U+202E, U+2066 to U+2069, U+061C), the zero-width characters (U+200B to U+200F, U+2060 to U+2064), the byte order mark U+FEFF and the rest of the category, 170 code points in all (U+00AD, U+0600 to U+0605, U+06DD, U+070F, U+0890 and U+0891, U+08E2, U+180E, U+FFF9 to U+FFFB, and the characters above U+FFFF in the Cf category, including the tag characters U+E0001 and U+E0020 to U+E007F; the set is derived from `unicode.Cf`, and a test pins that `strconv.IsPrint` rejects every one of them). Each is written as `\uXXXX`, one above U+FFFF as a surrogate pair, so the decoded value of every payload is byte for byte what it was and only the raw bytes of the printed line change; a plain payload prints exactly as before. A bidi override in a payload can no longer reorder or hide the text around it in a bidi-aware viewer of the `-json` output. The `time` field is not range-checked (not approved); the other non-printable characters (the non-ASCII spaces, private use, unassigned code points) stay raw in `-json`, as they did.* |
| 36 | **A consumer's committed offset is the next sequence to read.** `Commit(next)`; the idiom is `Commit(lastRead+1)`; the next read starts at the offset; `Lag = Head + 1 − offset`; a consumer is *behind* when `offset ≤ Head`; a caught-up consumer has `offset = Head + 1`. `Commit` accepts values from the first retained sequence to `Head + 1` and refuses others (`ErrOffsetRange`). A consumer file stores the log ID; a consumer whose stored ID differs from the log's fails with `ErrWrongLog`.
